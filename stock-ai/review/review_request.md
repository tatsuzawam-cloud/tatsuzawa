# 指示書①：オニール『成長株発掘法【第4版】』ルール抽出

## 0. 目的
この本を「要約」せず、日本株の成長株スクリーニングとバックテストに使える
**投資ルールのデータベース**に変換する。最終成果物は下記5つ。

| 成果物 | 保存先 |
|---|---|
| ルール一覧（人が読む用） | `knowledge/onil_rules.md` |
| ルール一覧（機械用） | `knowledge/onil_rules.json`（形式は `knowledge/rule_schema.json`） |
| 数値化できないルールの一覧 | `knowledge/onil_unquantifiable.md` |
| 要確認リスト（OCR不安・矛盾・曖昧） | `knowledge/onil_review_list.md` |
| 作業ログ（何ページまで処理したか） | `work/onil_progress.md` |

## 1. 絶対ルール
1. **本に書かれていること**と**あなたの推論**を必ず分ける（JSONの `source_type` が `book` / `inferred`）。
2. 本に書かれていない数値を作らない。数値が無ければ `threshold` は `null`。
3. 根拠ページを必ず付ける（スキャン画像のページ番号と、本の印刷ページ番号が違う場合は両方）。
4. 原文の引用は1件30字以内。本の文章を長く写さない（個人研究用でも、抜粋に留める）。
5. 日本株への適用上の注意は `japan_caveat` に書く。これは推論なので、本の主張に混ぜない。
6. OCRで読みにくい箇所・数字は、推測で補わず `ocr_confidence: low` にして要確認リストへ。
   **数字（%・倍率・日数・週数）は特に慎重に。** 数字が怪しいときは、該当ページの画像を直接見て確認する。
7. 著作物を外部サービスへアップロード・公開・GitHubへのコミットをしない（`books/` と `work/` は `.gitignore` 済み）。

## 2. 事前確認（最初に必ずやる）
1. `books/onil_canslim_4th.pdf` を開き、次を報告して私の確認を待つ。
   - 総ページ数
   - 文字が読める（テキスト層あり）か、画像だけか
   - 画像だけの場合は、OCRの方法（`ocrmypdf` 等）と日本語精度の見込み
   - 最初の3ページ分を試しに読み、文字化け・数字の誤読がないか
2. 目次から章構成を一覧化し、下の「3. 抽出の対象」と各章の対応表を作る。
3. 処理計画（何ページずつ、全何回に分けるか）を示す。**私が OK と言うまで本処理に入らない。**

## 3. 抽出の対象（14項目）
本の記述から、次の14分野のルールを漏れなく抜き出す。

1. 成長株を見つける条件（全体像）
2. CAN SLIM の各条件（C・A・N・S・L・I・M を1つずつ）
3. EPS（当期・年間・加速・質）
4. 売上高
5. 利益成長（利益率・ROE など）
6. 株価・出来高（チャートパターン、ベース、ブレイクアウト、出来高の増減）
7. 業界・市場（業界グループの強さ、相場全体の方向）
8. 機関投資家（保有、買い増し、質）
9. 買いのタイミング（ピボット、買ってよい範囲、買い増し）
10. 売却条件（利益確定の考え方、売りのシグナル）
11. 損切り条件（損失の上限、守り方）
12. 例外・注意事項
13. 数値化できる条件（まとめ）
14. 数値化できない条件（まとめ）

**1つの記述が複数分野にまたがる場合は、分野ごとに別ルールにせず、1ルールにして `category` は主たる分野、残りは `exceptions` か別フィールドで触れる。**
同じ内容の重複は統合し、統合元ページは `pages` に全部書く。

## 4. 処理の進め方（章ごとに区切る）
1. 計画で決めた区切り（目安：1回あたり20〜30ページ）で処理する。
2. 区切りごとに、`onil_rules.json` へ追記し、`work/onil_progress.md` を更新する。
3. 区切りごとに、**私へ3行で報告**する：新規ルール数／要確認の数／次に処理する範囲。
4. 全部終わったら、重複統合と ID の振り直し（ONIL-001 から連番）をする。

## 5. 各ルールに必ず付ける判定
- `quantifiable`：数値の条件に直せるか（true/false）
- `backtestable`：yes（株価・財務データだけで検証可）／partial（一部の判断が主観）／no（データ取得が困難）
- `data_needed`：検証に必要なデータ（例：四半期EPS、株価日足、出来高、業界分類、機関投資家保有）
  - 日本株で入手が難しいもの（機関投資家の保有推移など）は `backtest_note` に「日本での代替案」を書く。

## 6. 完了時のセルフチェック（報告前に必ずやる）
次を確認し、結果を表で報告する。**できていない点は隠さず、「できた所／まだの所／一番怪しい所」に分ける。**

| 確認項目 | 結果 |
|---|---|
| 全ページ処理したか（抜けたページ一覧） | |

| 売却・損切りのルールがあるか | |
| `threshold` が埋まっているルールは、すべて本の記述に裏付けがあるか（無作為に10件ページ画像で再確認） | |
| `source_type: inferred` のルール件数 | |
| OCR低信頼の件数 | |
| 矛盾する記述（本の中で条件が食い違う箇所） | |

## 7. 最終報告の形式（私が忙しい前提で）
1. 結論：ルール総数、数値化できる数、バックテスト可能（yes）の数
2. 日本株で検証する価値が高そうなルール TOP10（理由1行ずつ）
3. 要確認リスト（私が判断すべきことだけ）
