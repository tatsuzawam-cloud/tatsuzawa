# 指示書①（改訂版）：オニール『成長株発掘法【第4版】』ルール抽出

## 0. 目的と、いちばん大事な設計
この本を「要約」せず、日本株の成長株スクリーニングに使えるルールの表に変える。
**データは3つの層に分け、混ぜない。**

| 層 | 中身 | 作る人 | 保存先 |
|---|---|---|---|
| ① 原著ルール | 本に書かれていることだけ | この指示書で作る | `knowledge/onil_rules.json` |
| ② 仮説 | AIの推論、代替指標、日本株向けの調整 | この指示書で「案」だけ作る（承認前） | `knowledge/onil_hypotheses.json` |
| ③ 検証用の定義 | データ取得先、公表日の扱い、売買条件 | **指示書②で作る。ここでは作らない** | （後日） |

他の成果物：`knowledge/onil_rules.md`（人が読む用）／`knowledge/onil_review_list.md`（要確認）／`work/onil_progress.md`（作業ログ）。
型は `knowledge/schema/*.schema.json`。**保存のたびに `python3 -I tools/validate_rules.py knowledge/onil_rules.json knowledge/onil_hypotheses.json` を実行し、OKになるまで直す。**

## 1. 絶対ルール
1. 層①には、**本に書かれていることだけ**を入れる。推論・代替指標・日本株向けの注意は層②へ。
2. 本に書かれていない数値は作らない。数値が無ければ `conditions` は空配列、`quantifiable` は false。
3. 数値条件は `metric / period / comparison_basis / operator / value / unit` に分けて書く。
   「EPS25%以上」なら、四半期か年間か、前年同期比か前期比かまで、**本が書いている範囲で**埋める。本が書いていない項目は null。推測で埋めない。
4. 根拠は `evidence` に1件ずつ：PDFページ・本の印刷ページ・短い引用（30字以内）・OCR状態。統合したルールは、根拠ページを全部並べる。
5. 数字（%・倍率・日数・週数）は、**数値を持つ全ルール**について、根拠ページの画像を見て確認する（抜き取りではなく全件）。確認できたら `numeric_verified: true` と `verification_status: image_checked`。確信が持てなければ `needs_human`。
6. OCRで読みにくい箇所は推測で補わず、`ocr_status: low` にして要確認リストへ。
7. 原文の引用は1件30字以内。長く写さない。
8. 外部サービスへの本のアップロード、公開、GitHubへのコミットをしない（`books/` と `work/` は除外済み）。
9. **層②の仮説は、必ず `approval_status: pending` で作る。** 承認できるのは正彦さんだけ。承認前の仮説は、検証にも、ランキングにも使わない。
   代替指標を作るときは、`why_not_equivalent` に「原著のルールと、どこが同じでないか」を必ず書く。

## 2. 事前確認と試験運転（本処理の前に必ずやる）
1. `books/onil_canslim_4th.pdf` を開き、次を報告して私の確認を待つ。
   - 総ページ数／文字が読めるか、画像だけか／OCRの方法と日本語精度の見込み
   - 最初の3ページを試し読みして、文字化け・数字の誤読がないか
2. 目次から章構成を一覧にし、「4. 抽出の対象」との対応表を作る。処理計画（何ページずつ、全何回か）を示す。
3. **試験運転：まず10〜20ページだけ**処理し、検証ツールを通し、結果を報告する。
   見るのは、①型に収まったか ②数字を読み違えていないか ③本の記述と推論が混ざっていないか。
   **私が OK と言うまで、全ページの処理に入らない。**

## 3. 作業の進め方
1. 計画した区切り（目安：20〜30ページ）ごとに、層①へ追記し、検証ツールを通し、`work/onil_progress.md` を更新する。
2. 区切りごとに3行で報告：新規ルール数／要確認の数／次の範囲。
3. **IDは作った時に確定し、以後は振り直さない。** 重複は `status: merged` と `merged_into` で履歴を残す。
   統合してよいのは、**主張も適用条件も同じ**ときだけ。条件が違えば別ルール。迷ったら統合せず `review_note` に書く。
4. 複数の数値条件は `conditions` に並べ `logic`（AND/OR）を付ける。入れ子（ANDの中にOR）は表せないので、
   `review_note` に書き `verification_status: needs_human`。AIが独自に解釈して分解しない。

## 4. 抽出の対象（14項目）
成長株を見つける全体像／CAN SLIMの7条件（C・A・N・S・L・I・M）／EPS／売上高／利益成長／
株価・出来高（チャートパターン、ベース、ブレイクアウト）／業界・市場／機関投資家／買いのタイミング／
売却条件／損切り条件／例外・注意事項。数値化できる条件・できない条件のまとめは、最後に一覧で作る。

1つの記述が複数分野にまたがるときは、1ルールにして `category` は主たる分野にする。

## 5. 層②（仮説）に書いてよいこと
- 日本株に当てはめるときの注意（`japan_adaptation`）
- 取得しづらいデータの代替指標（`proxy`）。例：機関投資家の保有 → 別の指標で代用
- 数値を変えた案（`parameter_change`）
データが取れるかどうか、いつ公表されたかの扱いは、ここでは決めない（指示書②の仕事）。
層①には `uses_financial_disclosure`（決算など公表データを使う条件か）だけ印を付けておく。
